Every VM runs on the [crate engine](https://github.com/oneamendez/crate), so the
engine's speed is the whole app's speed. It's written from scratch in Rust: an
arm64-to-arm64 translator that copies most guest instructions into host code as
they are and rewrites only what touches the machine. It runs inside the app, on
the memory JIT lets crate claim.

Around it, the VM gets a virtio GPU whose frames go straight to the app, touch
and keys as a virtio tablet and keyboard, a serial console, and a user-mode
network through libslirp. On an iPhone the guest's OpenGL runs on the GPU through
virglrenderer, ANGLE and MoltenVK.

## On a Mac

A Debian 13 guest runs a fixed set of workloads once it has booted, and every
engine must print the same output as native. Seconds, medians of 3, on an M3
MacBook Air with 4 CPUs and 4 GB for the guest. Native is QEMU on Apple's
Hypervisor framework, and QEMU's TCG is QEMU 10.0.2's translator.

| One at a time | crate | QEMU's TCG | Native |
|---|---:|---:|---:|
| Boot to the benchmark | 2.97 | 13.80 | 1.82 |
| gcc -O2, one large file | 6.93 | 35.30 | 1.59 |
| `node -e 0` | 0.41 | 1.44 | 0.13 |
| Python loop | 1.36 | 12.97 | 0.26 |
| xz -6, 4 MB | 1.39 | 4.93 | 0.65 |
| 1000 process spawns | 0.52 | 4.42 | 0.13 |
| **The whole pass** | **24.5** | **130.5** | **9.1** |

## On an iPhone

An iPhone Duo (A20, iOS 27.1), with 3 CPUs and 1950 MiB for the guest, measured
on 2026-11-11, before the engine's latest speed work. Every output matched the
Mac's.

| | crate |
|---|---:|
| Root prompt, from the app's launch | 5.3 s |
| Desktop drawn, from the app's launch | 6.3 s |
| sha256, 100 MB | 84 ms |
| sort, 300,000 lines | 72 ms |
| gzip and gunzip, 50 MB | 363 ms |
| `claude --version` (Claude Code) | 165 ms |
| Headless Chrome: start, then a V8 loop of 10 million | 2.4 s |
